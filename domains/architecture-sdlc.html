Domain 1: Prepare agent architecture and SDLC processes

Choose work an agent can perform safely, with clear outcomes and GitHub-native review.

1. Architecture2. Tools3. Memory4. Evaluation5. Coordination6. Guardrails

What to recognize

A strong agent task has bounded inputs, a reviewable output, success criteria, controls, and evidence. Planning states intent; validation proves the result.

Inputs

Issue, failing test, PR comment, or workflow log defines the work.

Outputs

Branch, pull request, artifact, or test result makes work reviewable.

Controls

Limited tools, required checks, reviews, and rulesets constrain autonomy.

Decision guide

  • Use low autonomy for reading, searching, summarizing, and planning.
  • Use medium autonomy for scoped edits and tests on a branch.
  • Require human approval for production-sensitive, irreversible, policy, or security decisions.
  • Keep the delivery path visible: issue → branch → PR → checks → review → merge.

Recall checks

  1. What artifact shows that a plan was reviewed?
  2. Which control blocks an unreviewed merge?
  3. Why is “be careful” not an enforceable guardrail?
