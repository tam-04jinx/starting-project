Domain 5: Orchestrate multi-agent coordination

Divide work by ownership, make handoffs durable, and prevent agents from colliding.

1. Architecture2. Tools3. Memory4. Evaluation5. Coordination6. Guardrails

Use multiple agents only when work splits cleanly

Good patterns include coordinator/worker, reviewer/verifier, and plan → implement → review pipelines. Avoid parallel agents when work is inherently sequential or they must edit the same files.

needs

Orders dependent workflow jobs.

Artifacts

Pass review, audit, and plan files between jobs.

Matrix

Runs the same job for distinct agents or bounded areas.

Conflict controls

  • Give each worker a separate branch or disjoint file ownership.
  • Use committed files, PR comments, artifacts, or summaries for handoffs—not chat-only memory.
  • Use workflow-level concurrency with cancel-in-progress: true when only the newest PR validation run matters.
  • Use required checks and review before integration.

Recall checks

  1. What does needs: [review, audit] guarantee?
  2. When is workflow concurrency useful?
  3. Why is a shared mutable branch risky for parallel agents?
