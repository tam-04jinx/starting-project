Domain 4: Perform evaluation, error analysis, and tuning

Use observable evidence to identify a root cause before changing prompts, tools, or setup.

1. Architecture2. Tools3. Memory4. Evaluation5. Coordination6. Guardrails

Evidence first

Checks

Tests, linting, type checks, and scans show behavior and security signals.

Run evidence

Workflow logs and artifacts expose command, environment, and output failures.

Traceability

Session logs, PR comments, and audit logs show what happened and who acted.

Tuning order

  1. Check task clarity and success criteria.
  2. Check repository instructions and current conventions.
  3. Check tool scope and permissions.
  4. Check setup, dependencies, secrets, and runner environment.
  5. Check current repository and session state before considering model changes.

For example, an authentication failure during dependency installation points to package access or setup—not a reason to grant broad shell access.

Recall checks

  1. When should you tune instructions rather than tools?
  2. Which artifact setting turns a missing expected file into a failure?
  3. Which audit event records manual artifact deletion?
