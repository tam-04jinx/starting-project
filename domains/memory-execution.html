Domain 3: Manage memory, state, and execution

Know what persists, what can resume, and what evidence teammates can inspect.

1. Architecture2. Tools3. Memory4. Evaluation5. Coordination6. Guardrails

State types

Short-term context

Current prompt and session context; useful, but not a durable handoff.

Copilot Memory

Reusable repository facts or user preferences that must be checked for freshness.

Durable state

PRs, issues, commits, artifacts, logs, and check runs that are auditable.

Execution reasoning

  • A stable session ID enables session resume; memory and sessions are different concepts.
  • Use an artifact or job output to pass state between workflow jobs.
  • Use a PR comment or review to preserve a human decision.
  • Detect context drift by checking the current branch, re-reading files, and comparing assumptions with current evidence.
  • Never store secrets in memory, prompts, instructions, or comments.

Recall checks

  1. Which log evidence means a session was resumed?
  2. What durable artifact should carry a review decision?
  3. What can cause an agent’s context to drift?
